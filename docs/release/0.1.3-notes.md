# Circuit 0.1.3 Notes

Date: 2026-07-30

Circuit 0.1.3 is a fast-follow fix release for the Codex host. A live
end-to-end test of the published 0.1.2 Codex plugin found four bugs, all
in the boundary between Circuit and the Codex host rather than in the
engine. All four are fixed here, and each fix was proven again live
against a real Codex before this release was cut. The Claude host is
unaffected. There are no breaking changes for supported setups, but the
minimum Codex version rises: see the floor change below.

## Changed: the minimum Codex version is now 0.146.0

The prompt-only relay configuration Circuit sends includes fields that
only Codex 0.146.0 and newer accept. On 0.144 and 0.145 the old floor
allowed a run to start and then abort mid-relay with a confusing error.
The floor is now 0.146.0 everywhere: the preflight refuses an older
Codex up front, in under a second, with a message that names the
installed version and the required one. Preflight also now probes the
exact configuration shape the relay will send, so a config the host
would reject is caught before any run starts, not in the middle of one.

## Fixed: Codex 0.146 cache reinstall no longer wedges every session

Codex 0.146 reinstalls the plugin cache after spawning the MCP server,
which left the server running in a deleted directory. Circuit's
preflight probes inherited that dead directory, failed, and blamed the
wrong thing, telling the operator to update an already-current Codex.
The server now anchors itself to a durable directory at boot, probes
spawn from a durable directory, and preflight errors include the probe's
own words so a wrong diagnosis cannot hide. The full lifecycle was
re-proven live with the server's spawn directory deleted at birth: the
run started, relayed to a real nested Codex, and closed honestly.

## Fixed: invalid start options are refused clearly, up front

A start request with an option the selected flow does not support, such
as asking Review to run at a process depth it does not offer, used to
pass the start schema and die deep inside the worker with a bare exit
code and no explanation. The start boundary now validates process,
tournament, and autonomous against the same packaged flow definition the
engine enforces, and refuses with a plain sentence naming the allowed
values and the next step.

For failures that do still reach the worker, Circuit now keeps the tail
of the worker's own error output and repeats the human-readable part in
the run's failure summary. A worker that dies on its first breath leaves
its explanation in the run evidence instead of a mute exit code.

## Fixed: headless Codex sessions can now watch, list, and repair runs

Headless Codex (`codex exec`) auto-cancels any MCP tool call whose tool
is labeled destructive (upstream issues openai/codex#16685 and
openai/codex#24135). Circuit labeled every tool except `circuit_list`
destructive, so a headless session could not even poll a run it did not
start. Labels are now honest per tool: `circuit_status` and
`circuit_recover` only maintain Circuit's own run records and are no
longer labeled destructive, so headless sessions can watch, list, and
repair runs. Starting, resuming, and cancelling a run keep the
destructive label they deserve and still require an interactive session
until the upstream issues ship a headless approval path. Both halves
were proven live: a headless session read run status successfully, and a
headless start was still refused by Codex.

## Noted openly

The recorded end-to-end first-run proof for the Codex MCP host remains
an approved exception, as it was for 0.1.2. The live test that found
these bugs, and the live re-proof that verified the fixes, are exactly
the evidence that proof gate exists to capture; building its recorded
producers is the standing follow-up.
