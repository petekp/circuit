# Circuit 0.1.0 Notes

Date: 2026-07-13

Circuit 0.1.0 is the first public release. It ships the same two host
plugins as the alphas (Claude Code and Codex) plus the standalone CLI on
npm as `@petekp/circuit`. Two themes separate it from 0.1.0-alpha.10: the
operator surface settled its vocabulary, and the release passed a new
failure-legibility gate. A run may fail; it may not fail unexplained.

## Breaking: the operator surface settled its names

- `--depth` is now `--process`. The power dial derives a sensible process
  level when you do not set one, so most runs need only `--power`. Run
  receipts print power first, then process.
- `circuit inbox` is now `circuit checkpoints`, matching what it lists.
- The per-flow config key `circuits` is now `flows`. Update
  `.circuit/config.yaml` files that pin per-flow connectors.
- `--tournament-n <n>` folded into `--tournament [n]`. Bare `--tournament`
  keeps the default fan-out.
- Pursue is no longer a public flow. It runs from a source checkout while
  its shape settles post-v1. The public set is build, explore, fix,
  prototype, and review.
- `circuit doctor` grades readiness on the connectors your runs would
  actually use. Optional connectors are reported but no longer fail the
  check, so exit `0` means the chosen set is healthy.

## The failure-legibility gate

Adopted after a field failure: a healthy worker was killed at a 3-minute
silence bound that lived only in a source comment. The standing rule for
this and every future release: every terminal outcome names what happened,
whose fault it was, and what to do next, and every limit an operator can
hit is visible in docs or in the failure message itself. The audit record
is [docs/audits/2026-07-13-failure-legibility-hardening.md](../audits/2026-07-13-failure-legibility-hardening.md).
What it changed in this release:

- Workers get 600 seconds of silence before the watchdog steps in, up
  from 180. A step whose relay is legitimately quiet for longer can set
  `budgets.inactivity_ms`. Custom connectors get the same 60-minute
  wall-clock backstop as the built-ins (was 2 minutes) and no default
  silence bound at all. Every timeout message names the bound that fired
  and the setting that loosens it.
- Failure messages lead with the fact. A launch failure says the CLI is
  missing or signed out before showing the raw error. A verification
  abort names the failing command, its exit code, and its last output.
- Every subcommand has real help, and wrong invocations exit `2` with a
  message that answers in one step instead of masquerading as engine
  failures.
- Read surfaces tell the truth. `circuit preview` marks the steps a
  process dial skips. `circuit config show` reports where each value
  actually comes from. Doctor remedies are paste-workable commands. JSON
  surfaces carry `schema_version` stamps. Empty states point at the next
  command.
- A run folder with no recorded outcome now says so: the `open` status
  carries a notice that the run is either still in progress or was
  interrupted, instead of looking identical to a live run.
- The operator summary stops hiding what it knows. Capped lists say how
  many entries they dropped, machine warnings can never be evicted by
  ordinary caveats, and a recovery-binding abort leads with a plain
  explanation of whose problem it is (the flow definition) above the
  verbatim reason.
- Fail-safe seams that used to swallow their own crashes now leave trace
  markers naming the step and the cause, while the run still completes.

## Also new since alpha.10

- The CLI installs directly from npm: `npm install -g @petekp/circuit`.
  The release gates prove the packed tarball installs and runs on a clean
  machine.
- The pre-launch security audit is remediated on this release, with the
  public record at
  [docs/audits/2026-07-09-pre-launch-remediation.md](../audits/2026-07-09-pre-launch-remediation.md).
- Verification budgets are shared across attempts and their timeouts are
  honest, so a slow check cannot silently eat a step's whole budget.
- Review binds its terminal outcome to the verdict: an issues-found
  review closes `stopped` instead of reading as a crash, and a green
  build with a review reject stops honestly.
- Running the CLI from a directory with no compiled flows falls back to
  the flows bundled with the installed package, so `circuit run` works
  from any project.
- Passing a directory inside `.circuit` as a project root no longer nests
  a second control plane inside the first.

## Release process

This release followed the standing runbook
([docs/release/runbook.md](runbook.md)). The first-run container lab ran
before the version bump and again after publishing, replaying the
documented install funnels in clean containers with no credentials and no
model spend.

## Checks

The standard release gates apply: `npm run verify`,
`npm run check-release-ready`, and the publish gate suite in
`npm run publish:plugins:release`.
