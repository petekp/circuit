# Circuit 0.1.4 Notes

Date: 2026-07-31

Circuit 0.1.4 fixes the last known first-launch defect in the Codex host
and records the first paid end-to-end proof of the Codex MCP path. The
Claude host and the engine are unaffected. There are no breaking changes.

## Fixed: the first start of a session no longer races the cache reinstall

Codex reinstalls the plugin cache shortly after every session start, and
the reinstall lands after the MCP server is already running: the same
bytes come back under the same paths with fresh file identities. Circuit
seals the runtime files it will execute when a run starts, and that seal
compared file identity strictly, so a start that landed in the reinstall
window was refused as drift and the first launch of a session could fail
with nothing wrong. The seal now compares what actually matters — path,
content digest, permissions, and size — and pinning retries through the
reinstall window. A same-path, same-content reinstall passes; any content
change is still refused before start or resume, exactly as before.

A start that fails to launch now also records why. The failure record
carries the underlying cause instead of a generic sentence, so a refused
launch is diagnosable from the run's own evidence.

## Recorded: a paid first-attempt Review proof through real headless Codex

The release evidence now includes a full first-attempt Review captured
through a real headless Codex on a fresh, isolated host: one start call,
cursor-based status polling, a clean verdict, every artifact bound by
content digest to the exact candidate commit, and the operator-side
pre-approval of the one start tool recorded openly in the evidence. The
capture pipeline that produced it is committed and repeatable.

## Changed: the release system now promises only what it checks

A first-principles review of the release machinery retired two pieces
that had outlived their purpose. A dormant validator demanded an
every-flow-and-mode capture matrix that no script produced and whose
runs would mostly re-prove the one shared MCP lifecycle the recorded
Review already proves; the proof contract now states exactly what the
checker binds. And the original-Circuit parity comparison, whose
migration-fidelity job completed in June, moved from the per-change
gate suite to an archived historical record. Proof contracts are now
required to label their prose as script-checked or narrative.

## Noted openly

The recorded Codex first-run proof remains an approved exception with
two named gaps: this tag is the first to carry the first-launch fix the
recorded proof exercised, and the same Review capture has not yet run
on an Intel Mac. Loader-level coverage on both architectures continues
to run in CI against every change.
