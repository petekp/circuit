Architecture audit

Circuit is a flow compiler, runtime engine, worker router, and evidence recorder.

The clean center is strong: flows are authored as data, compiled into generated surfaces, executed by a flow-agnostic runtime, and recorded as typed evidence. The main drag on beauty and simplicity is not the core idea. It is a few crossings where authoring, runtime routing, presentation, and shared helpers know too much about each other.

What is already beautiful

Catalog-derived flows, generated-surface drift checks, typed run evidence, and boundary tests keep the product understandable.

What is currently complected

shared and flows cycle; one flow writer reaches into connector routing; app and memory form a service cycle.

Best next simplification

Break presentation and routing decisions out of generic helpers and flow writers. Let flows declare; let app/runtime services decide.

catalog as source of truth runtime is mostly flow-agnostic wide schema barrel top-level import cycles CLI orchestration hotspot

Whole System

Circuit turns an operator intent into a chosen flow, executes that flow through worker relays and local executors, then writes trace and report evidence that can be summarized, resumed, recalled, tested, and shipped through host plugin packages.

Runtime System

Runtime reads a compiled graph, runs one step at a time, gates the result, follows the route, and records durable trace entries. It should continue to know execution mechanics, not product-specific flow behavior.

run-files/Run-folder paths and report validation.Good boundary: file persistence has one home.

Run Front Door

Run is a decision timeline, not one decision. It chooses the flow early, but connector, model, effort, skills, and connector options are resolved later per relay step.

Contracts

Schemas are the system's contract layer. This is the right dependency direction: almost everything imports schemas, and schemas import no source layer. The cost is surface area: the root schema barrel re-exports 50 files and the schema package has 858 exports.

Connectors And Selection

Connectors are chosen per relay. The order is explicit step input, policy envelope preference, selection config, then host-aware auto fallback. Policy hard constraints then validate the connector, provider, effort, and skill plan before relay execution.

Evidence System

Run evidence is the product's strongest audit primitive. The runtime writes manifest, trace, reports, and results. App and shared services project those files into summaries, run status, process evidence, history input, release proof, and operator-facing HTML.

Memory And History

History recall is deliberately hint-only. It narrows candidates to the selected flow, applies earned precision, writes recall reports, and injects memory inputs into runtime relay composition without changing routing, checkpoint choices, or proof authority.

Skill Hooks

Skill Hooks are actively being implemented. Current workspace source records run.skill-hook events and, for auto policies, injects the resolved skill ids into a run-scoped channel that later implementer relay guidance loads into the worker prompt. Reviewer and researcher relays stay uninjected. ask remains a decision-packet shape, not a pause in the live loop.

Release, Evals, And Tests

The verification surface is broad and useful. Contract tests protect boundaries, drift checks protect generated surfaces, eval checks keep evaluation plumbing honest, and release checks validate public claims and proof coverage.

Seam Findings

These are architecture findings, not immediate bug reports. The point is to identify where future change will feel heavier than it should, then name the simpler shape.

High shared is not purely shared

Pattern: inappropriate intimacy, middle-man pressure, cycle.

Evidence: flows -> shared has 32 edges, while shared -> flows has 6 edges. The cycle runs through operator summary and flow catalog/projector wiring.

  • Indictment: shared helpers and flow-aware presentation orchestration live under the same label.
  • Correct shape: keep shared as pure utility; move flow-aware summary orchestration to an app or runtime close service.
  • Benefit: breaks the most central cycle and makes "shared" mean one thing.

High Prototype flow writer reaches into connector routing

Pattern: feature envy, dependency direction leak.

Evidence: src/flows/prototype/writers/variant-options.ts imports src/connectors/resolver.ts to validate variant connector/model compatibility.

  • Indictment: a flow report writer is deciding worker-routing compatibility.
  • Correct shape: flow writer declares requested variant selections; a selection planning service resolves and validates connectors.
  • Benefit: flow packages stay declarative and connector policy stays in one place.

Medium Schema root barrel is too wide

Pattern: god module risk.

Evidence: src/schemas/index.ts re-exports 50 files; src/schemas has 858 public exports and 10 top-level fan-in.

  • Indictment: consumers can import the whole contract warehouse when they need one family.
  • Correct shape: introduce family entrypoints such as flow, run, host, policy, and evidence.
  • Benefit: smaller import surfaces and clearer contract ownership.

Medium CLI is a front-door hotspot

Pattern: shotgun-surgery risk.

Evidence: src/cli/circuit.ts has 33 local imports and coordinates routing, axes, fixture loading, config, history recall, runtime invocation, resume, and post-run output.

  • Indictment: user command parsing and run orchestration are too close.
  • Correct shape: move fresh-run and resume use cases into app services; keep CLI as parse and print.
  • Benefit: less CLI churn when runtime behavior changes.

Medium App and memory form a service cycle

Pattern: misplaced ownership.

Evidence: app -> memory and memory -> app. Memory uses the app history indexer while app history recall loads memory project facts.

  • Indictment: memory and history share storage mechanics but import each other through service layers.
  • Correct shape: split a history-store core below both app history and memory injection.
  • Benefit: memory can evolve without becoming an app subservice or vice versa.

Medium Flow policy authority points both ways

Pattern: ownership ambiguity, cycle.

Evidence: policy -> flows imports canonical stage policy, while flow packages import policy rubric state for Explore and Prototype decisions.

  • Indictment: policy is described as a separate layer, but some policy authority lives in flows and some flow scoring input lives in policy.
  • Correct shape: either make flow-domain policy part of the flow system, or move canonical stage and rubric authority below both flows and runtime consumers.
  • Benefit: one owner for flow-kind and rubric rules, with fewer surprise imports.

Medium File-surface metadata is centralized in skill hooks

Pattern: parallel hierarchy risk.

Evidence: src/skill-hooks/surface-sources.ts maps report schema strings to extractors for Fix and Build edit-file hooks.

  • Indictment: as more reports expose file surfaces, skill hooks may need a matching central edit for each flow report.
  • Correct shape: put surface metadata in flow report declarations and compile it into runtime surface registries.
  • Benefit: adding a flow report does not require knowing the skill-hook dispatcher.
